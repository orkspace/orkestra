# `pkg/resources` — Kubernetes Resource Library

The `pkg/resources` package is the standard library of Kubernetes resource operations used across Orkestra. It provides idempotent, owner-reference-aware Create, Update, Delete, and Resolve functions for every resource type.

It started as the layer `GenericReconciler` dispatches to when processing declarative templates, but it has since grown into a general-purpose library: hooks and constructors call these functions directly too. See `examples/advanced/09-hooks`, `examples/advanced/10-constructor`, and `examples/from-controller-runtime` for real usage from user-written Go code.

---

## Structure

Each resource kind gets its own subdirectory (`deployments/`, `services/`, `roles/`, and so on — one per Kubernetes/custom resource kind Orkestra manages), plus two shared ones:

- `common/` — shared utilities: probes, security, volumes, rolling update
- `template/` — the Resolver: evaluates Go templates against live CR fields

Each resource subdirectory exports six functions: `Create`, `Apply`, `Update`, `Delete`, `DeleteIfOwned`, and `Resolve`.

---

## The contract

- **Create** — sets owner references and system labels (`managed-by: orkestra`, `orkestra-owner: <cr-name>`). No-op if the resource already exists. Used for resources that are never updated after creation (`onCreate:` hooks).
- **Apply** — Server-Side Apply via `ApplyPatchType` with `fieldManager: orkestra-runtime`. Sends only the fields Orkestra declares; k8s-injected defaults (token volumes, security contexts, etc.) belong to a different field manager and are untouched. Idempotent — safe to call on every reconcile. Used by `onReconcile:` hooks.
- **Update** — delegates to `Apply`. Kept for backward compatibility with existing callers.
- **Delete** — no-op if the resource does not exist.
- **DeleteIfOwned** — deletes by name/namespace only if the existing resource's `orkestra-owner` label matches the caller's owner. No-op otherwise, including when the resource doesn't exist. Used for conditional cleanup — e.g. when a `when:` condition stops matching and a previously-created resource should be removed.
- **Resolve** — takes a template source (with potentially unresolved field values) and returns a fully resolved spec.

Resources that use **Create-only** semantics (no Apply): `jobs`, `serviceaccounts`, `pvcs` — their specs are immutable or managed externally after creation.

All functions receive a `kubeclient.KubeClient` and a `domain.Object` (the owner CR). They never assume the owner's concrete type.

## Adding a new resource type

1. Create `pkg/resources/<kind>/` with `<kind>.go` and `types.go`.
2. Define the `*TemplateSource` struct in its own `pkg/types/types_<kind>.go`,
   then add a field for it to `HookTemplates` in
   `pkg/types/types_hook_templates.go` — that's what actually exposes it
   under `onCreate`/`onReconcile`/`onDelete`.
3. Add a resolver method in [`pkg/template/resolver.go`](template/resolver.go).
4. Add the runner in `pkg/runtime/reconciler/run_<kind>.go`.
5. Call the runner from [`pkg/runtime/reconciler/generic.go`](../../pkg/runtime/reconciler/generic.go).
6. Give the `*TemplateSource` struct and every exported field a Go doc
   comment — these are the source of truth for the published schema docs
   ([`documentation/reference/schema/06-resources/`](../../documentation/reference/schema/06-resources/index.md)), generated by
   `make generate-resource-docs`. Cross-cutting fields shared by every
   resource kind (`labels`, `annotations`, `when`, `reconcile`, `or`,
   `forEach`, `sleep`) already have established wording in the other
   `types_*.go` files — copy that text verbatim rather than rewriting it, so
   the same field reads identically across every resource's doc page. Any
   field typed as a pointer-to-struct or slice-of-struct needs a worked YAML
   example in its comment (see [`pkg/types/types_deployment.go`](../../pkg/types/types_deployment.go) for the
   pattern).
7. Add an entry to the `kinds` slice in [`hack/generate-resource-docs/main.go`](../../hack/generate-resource-docs/main.go)
   — the doc comments from step 6 are only picked up for kinds registered
   there. A new resource with perfect doc comments but no `kinds` entry
   silently gets no doc page at all. Then run `make generate-resource-docs`
   and confirm the new page has no leftover "Go type" or Go identifier
   leaking into the output.

See [`pkg/resources/deployments/`](deployments/) for a complete example.
